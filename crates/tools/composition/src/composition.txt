// Round this visual's composed position to whole device pixels. It governs where the

// A step easing HOLDS its value across a step and jumps, rather than producing a
// fresh value every vblank. That is a rendering choice for a curve that has to land
// on discrete positions, but it is also the only lever a key-frame animation has over
// how OFTEN it writes: a continuously-eased animation on a visual's Offset rewrites
// that Offset every frame, and the compositor invalidates the visual's whole bounds
// each time — old bounds and new — however small the delta. For a large, slow-moving
// sprite the delta can be a fraction of a pixel while the invalidation is a large
// fraction of the window, so the cost is set by the write RATE and not by the
// distance travelled. Stepping decouples the two: the path and its duration are
// unchanged, only the number of distinct positions along it is chosen.
Windows.UI.Composition.StepEasingFunction
